### This is a separate README file solely for navigating using the Flux Balance Analysis Model Building Aspect of this Repository ###

The two Excel files: Production Pathways and Substrates Overview, are simply detailed overviews of the pathways and substrates we used in our own investigations. They do not need to be modified, and simply serve as a reference

Within the Code Files folder, there are 3 folders and 4 notebooks, BuildProductModels and CheckModels are linked to CreateProductModels, and the other two are linked to the folder sharing the same name. This folder serves as a way to perform Flux Balance Analysis on multiple feedstocks and substrate utilization pathways concurrently. It can only handle performing FBA on one model at a time, so if you wanted to investigate pathways in the iJO1366 and iML1515 models, you would need to repeat this process twice (although saving outputs between steps will prevent you from needing to continuously regenerating models)

#### Step 1 ####
Within the CreateProductModels' Input folder, include Excel files of all the desired final products you wish to try to produce in the hybrid system. The Final XLSX Models folder consist of the Excel files we used in our investigation to give some idea on the expected format. Of note, the metModels column is not required, and any notes written in the metNotes are solely for the user and not included in the final output. Once all your desired products are in separate Excel files in the Input folder, run the BuildProductModels notebook (making sure you specify a model from BiGGs or upload an xml file of the target organism under investigation). If everything runs without error, the CreateProductModels' Output folder will contain multiple separate xml files, each corresponding to an input bioproduct. (Optional), you can run CheckModels on that Output folder to see if everything is properly mass and charge balanced.

#### Step 2 ####
Copy those xml files into the Input folder of the ModifyModels folder. You will notice that there is another folder labelled EditModels in this Input folder. Do not add the xml files into that folder, leave them at the same level. The EditModels folder is there so you can add any additional assimilation pathways that are not present in the base BiGGs model or organism's xml file. We investigated 14 additional utilization pathways, which are archived in their respective model's folders to serve as formatting reference. Make sure any additional pathways you wish to add are in the same Excel file format and are kept in the EditModels folder, and not within the archived iHN637 or iJO1366 folders. After this is done, run the ModifyModels notebook, which will add these additional pathways one at a time to each bioproduct xml. The resulting Output folder will contain a new xml for each bioproduct xml.

#### Step 3 ####
Now copy those xml files again into the Input folder of the RunModels folder, but now within the XMLfiles folder. Before the final RunModels notebook is executed, some modifications need to be made in the Bioproducts_ModelInput and a corresponding SubstrateUptakePW_Reactions file. Bioproducts_ModelInput simply requires you to add the name, composition, and molar mass of your bioproduct (so mass yield can be calcaluated and the final output is in a generalized format). For the SubstrateUptakePW_Reactions file, either make a new one (and change the file name within the RunModels notebook), or modify an existing one to include your additional ***ECR product*** (which is the feedstock into the bioproduction system). You can use the existing files as a format reference, but since it is a bit confusing, the format is explained below, starting from the leftmost column of the Excel file:
* The compound name: This needs to be consistent with the substrate name you declare in the RunModels notebook. Keep in mind this is the name of the compound coming out of the ECR system (the ECR product/the hybrid system "intermediate"/the bioproduction feedstock), and not your final bioproduct. Make sure you differentiate if an intermediate is utilized in multiple biopathways, e.g. 'Formate_Formolase' and 'Formate_RGP-Serine'
* The molar mass of the compound (which again is the ECR product, not the final bioproduction product which the xml files are named after)
* The RxnID of the exchange reaction, followed by comma separated values for said reaction when the pathway is active versus non-active. To clarify, for the exchange reaction, this reaction should always exist in the reverse direction when the pathway is active (so you can actually produce your target bioproduct), and corresponds to a value of -1 (refer to the info sheet within the Excel file for a legend). The second number is the state of the reaction natively in your organism (essentially what it should be when this target pathway is "off"). For example, for formate in iJO1366, the organism naturally consumes formate, so the value in this column would be "EX_for_e, -1, 1"
* Multiple columns which stretch from the exchange reaction to the final added reaction. If the sheet doesn't have enough columns, simply insert more, ensuring that the final reaction is under the column name 'ReactionF'. The above pathwayON and pathwayOFF values are still required, so these will still be in the form of "RxnID,'pwON value,'pwOff value'"
* The central carbon metabolism of the pathway
* Status (Optional), good to keep track of a working document if required
* Notes (Optional)

#### Step 4 ####
Now that all the intermediates, products, and additional assimilation pathways are set up, run the RunModels notebook, specifying which intermediates you wish to investigate (as the model can take quite long to run on a personal device with a large number of desired intermediates and products) and the modelID (the iHN637 model requires a slightly different format in Step 3, for simplicities sake just avoid using the iHN637 model, and even if you do, try to bypass the iHN637 FBA function unless you are specifically working with H2 gas mixtures). The final output will be in the FBA folder within the Output folder in the RunModel folder. There will be separate Excel files, each consisting of a flux map for each intermediate + bioproduct combination. Furthermore, within the Summaries folder, there will be summarized results for each intermediate + bioproduct combination, as well as an overall summary of each combination together in one Excel file. That overall summary is what is required to update the FBA_OverallSummary Excel file in the main Input folder.
